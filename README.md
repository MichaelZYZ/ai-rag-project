# 产品说明智能问答机器人（课堂演示）

根据两份设计文档实现的可运行 MVP。内置的“星云笔记”和“轨道任务”完全是**虚构演示产品**；评估结果只说明这组小样例的表现，不代表生产效果。

## 快速启动

需要 Python 3.9+。Windows 双击 `start_windows.bat`；macOS 双击 `start_mac.command`，或在终端运行 `./start_mac.command`。脚本会创建 `.venv`、安装依赖、导入演示数据并启动服务。首次安装依赖需要联网。若旧服务占用 8000 端口，脚本会选择下一个空闲端口；请以终端打印的地址为准，不要继续使用旧的 8000 标签页。

macOS 也可以在项目目录手动运行：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python seed.py
uvicorn app.main:app --reload
```

访问启动终端打印的地址（通常为 http://127.0.0.1:8000 ，若该端口被旧服务占用则自动换用其他端口）。API 文档位于 `/docs`。`python evaluate.py` 会在临时数据库中导入示例资料并运行 8 个可复现的问题，不会污染演示数据。

## 演示路线

1. 聊天窗口顶部列出咨询次数最多的 6 个产品名称；若尚无咨询记录，列出所有已有知识库的产品。列表可点击标题展开或收起，选择产品后自动收起。点击“星云笔记”，在 2.0 版本问“最多支持多少个标签？”，查看 20 个标签和来源。
2. 切换到 1.0 问同样问题，查看 10 个标签，展示版本隔离。
3. 问“附件大小限制是多少？”，然后追问“那最多多少 MB？”，展示会话上下文。
4. 问“支持语音转写吗？”，展示资料不足时拒答；问“我要退款”，展示转人工摘要。
5. 点击“切换产品”查看全部已有知识库的产品；也可搜索“邮件提醒”，或直接问“有没有轨道任务的知识库？”。输入“有没有火星商城的知识库？”会提示联系人工。
6. 上传自己的 Markdown、TXT、HTML、HTM、DOCX 或可提取文字的 PDF；看右侧知识缺口与统计。
7. 点击聊天窗口标题旁的“+ 补充知识缺口”，或右侧“知识缺口”下的“+ 手动补充问答”，选择产品、版本并填写问题和答案；即使当前没有知识缺口也能补充。有缺口时也可点击该问题旁的“+ 补充答案”；再次提问可看到“人工补充”来源。
8. 点击右侧看板的“启动自我训练（整理问答）”，按需扫描已有资料并补充有原文依据的常见问答；服务启动不会自动执行此操作。

## 资料导入与清洗

上传 `.txt`、`.md`、`.html`、`.htm`、`.docx` 或可提取文字的 `.pdf` 后，系统依次执行：文字提取 → Unicode/全角 ASCII 与换行规范化 → 去除不可见控制字符和多余空白 → 过滤明确的页码行、空行与相邻重复行 → 保留标题并合并短标签/数值行 → 按 360 字切片（长片段重叠 50 字）→ 向量化入库。HTML 会提取可见正文、保留标题和段落分隔，忽略脚本、样式、导航和页脚；支持 UTF-8 及声明编码的页面。产品事实中的数字和单位不会被主动改写。

上传结果和知识管理列表会显示原始/保留行数及各类删除数量；同一份统计也保存在文档记录的 `cleaning_report` 字段。已有的示例资料会在再次运行 `seed.py` 时重建；此前上传的旧资料需重新上传才能应用新流程。扫描版 PDF 仍需先用 OCR 转成可提取文字。

## 常见问题整理与回答

导入资料时，`app/faq.py` 会识别 `Q:/A:`、`问题:/答案:` 以及同一行的问答对；也会从**明确写出的事实**生成常见问法，包括功能是否支持、数量/文件大小限制、操作步骤、忘记密码、价格、保修期、适用场景和兼容性。生成的答案直接保留文档原句，按产品、版本和来源存入 `faqs` 表，不会凭常识补出未写明的价格或能力。上传结果会显示整理出的常见问题数量。

选择产品后，聊天窗口提供最多 6 个可点击的常见问题。提问时先匹配同产品、同版本的 FAQ；匹配充分则返回原文答案和来源，否则回退到片段检索。相同问题在同版本资料中出现不同答案时转人工确认。可通过 `/api/faqs?product_id=...&version=...` 检查整理结果。

服务启动只初始化数据库，不会执行问答训练。点击看板的“启动自我训练（整理问答）”后，系统才扫描已有产品资料，按明确的介绍、功能、操作和参数段落生成常见问法，并核对答案的每一行都来自原文，再按产品、版本及来源补充缺少的 FAQ。重复点击不会重复添加；演示看板的“自动问答”显示由规则或段落生成的 FAQ 数量。新上传的资料会保存清洗后的原文以便后续重新整理；旧资料会从已保存的片段尽量补建，若旧片段已丢失原始问答结构，需重新上传原文件。

手动整理逐份读取资料、每批最多向量化 64 条问答，避免一次把全部原文和问答向量放入内存。耗时仍随资料数量和长度增加。

这里的“自问自答训练”是基于资料的问答整理和检索增强，不会修改模型参数，也不会把机器人自己生成的回答当成新事实。规则提取无法理解复杂表格、图片、扫描件和隐含语义；自动生成的问法应由产品负责人审核后用于真实客服。退款、投诉等敏感业务仍转人工。

## 手动补充知识缺口

聊天窗口标题旁与右侧“知识缺口”区域都有固定的补充入口，点击后在弹窗中选择产品和版本，以问题/答案格式保存人工 FAQ；无需先产生知识缺口。无答案问题会进入右侧列表，按产品和版本区分，也可点击对应的“补充答案”，保存后从未解决列表中移除。答案立即进入该产品版本的检索范围。已有产品和版本的缺口只能补到原范围，避免把答案写到别的产品。若同一问题已有不同答案，接口会阻止写入并提示核对。演示环境没有管理员鉴权，真实部署前需要增加权限和审核流程。

## 设计与边界

- `app/core.py`：文档解析、按事实行切片、4096 维字符 n-gram HashingVectorizer、SQLite 中保存向量、产品和版本过滤、余弦检索与字符重叠重排、会话编排与转人工。字符向量是**离线检索基线**，不是预训练语义 Embedding；生产部署可换成语义模型和专用向量库。
- `app/main.py`：FastAPI 接口。`app/static/index.html`：问答、导入和看板页面。
- 热门产品只统计已有资料的产品，按用户提问次数排序，最多展示 6 个；完全没有咨询记录时展示所有已有知识库的产品。“切换产品”始终列出所有已有知识库的产品。产品搜索会匹配名称、别名及知识片段，并把相似结果作为候选交给用户选择。匹配不足时提示联系人工，不自动把相似产品当成目标产品。
- `data/demo_knowledge.json`：虚构语料；`data/eval_cases.json`、`evaluate.py`：测试问题、期望状态、答案关键字和来源命中率。
- `prompts/answer.txt`：可选 LLM 的完整系统提示词。设置 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 后调用兼容 OpenAI Chat Completions 的接口；未设置时直接返回命中原文。不要把真实密钥提交或打包。
- 检索阈值 0.16 仅为演示样例的起点。上线前应扩大测试集、标注正确证据，校准阈值并补充冲突检测。扫描版 PDF 没有 OCR。网页、Excel、鉴权、限流和人工工单系统集成不在此 MVP 中。

数据保存在 `data/rag.sqlite3`，删除该文件可重置。演示服务默认无鉴权，请仅在本机运行。

## 失败案例与改进方向

- “支持语音转写吗？”在示例资料中没有依据，系统拒答。阈值基于小样例，类似措辞仍可能误判，需要更多无答案问题校准。
- “支持导出 Word 吗？”与“导出 PDF”语义接近，纯字符检索可能误命中；演示版对问题中的英文格式名做显式核对。更多参数和否定表达仍需结构化抽取与证据校验。
- 多轮追问只拼接上一轮问题；较长会话和复杂指代可能改写错误。生产方案应使用专门的指代消解并评估改写质量。
- 可选 LLM 的输出依赖提示词约束，尚未实现逐句忠实度验证，因此不能将小样例的命中率解释为生成忠实度。
